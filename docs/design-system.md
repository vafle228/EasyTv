# Дизайн-система EasyTv

Основа — текущий интерфейс; внешних макетов нет. Действующий источник значений — `frontend/src/styles.css`, поведения — компоненты React. Старые комментарии о генерации из `tokens.json` и внешних макетах исторические: этих файлов в репозитории нет. Эта документация не вводит генератор CSS и не меняет визуальный стиль.

## Направление

Мягкие объёмные поверхности, скруглённые карточки, спокойный фон, сине-фиолетовые основные действия и тёплые акценты. Основной пользователь управляет с телефона: найти → сохранить → выбрать телевизор → смотреть. Компьютерный интерфейс и загрузка файлов дополняют этот сценарий.

## Токены

| Назначение | CSS-переменные / значения |
| --- | --- |
| Брендовые цвета | `--peach: #ffbe8d`, `--coral: #ff8a8c`, `--blue: #5871f3`, `--indigo: #5345ba` |
| Основа | `--midnight: #0e0548`, `--ivory: #f3f1ee`, `--night: #1a1638` |
| Семантика | `--bg`, `--ink`, `--muted`, `--soft-ink`, `--danger`, `--on-primary` |
| Отступы | `--space-xs/sm/md/lg/xl`: 4/9/14/18/22 px; `--space-card`: 28 px; `--space-page`: 36 px |
| Скругления | `--r-card`: 28 px; `--r-inner`: 20 px; `--r-tv`: 22 px; `--r-pill`: 999 px |
| Объём | `--raise`, `--raise-sm` — выступающие поверхности; `--press` — утопленные |
| Градиенты | `--grad-primary` — blue → indigo; `--grad-warm` — peach → coral; `--grad-progress` — coral → blue |
| Шрифт | `--font-sans`: Manrope, system-ui, -apple-system, Segoe UI, sans-serif |

Базовый текст — 16 px с межстрочным интервалом 1.55. `.small` — 0.875rem; `.label` — 0.85rem, 700, верхний регистр и увеличенный межбуквенный интервал; `.heading` — 1.75rem, 700. Повторно использовать существующие классы вместо новой шкалы для каждого экрана.

Светлая тема использует ivory-фон и midnight-текст. Тёмная через `[data-theme="dark"]` переопределяет семантические цвета и тени. Поддерживаются светлая, тёмная и системная темы; выбор сохраняется в браузере. Новые поверхности должны использовать семантические переменные, а не фиксированные цвета светлой темы.

## Компоненты и состояния

| Элемент | Где переиспользовать |
| --- | --- |
| Навигация | `AppBar`, `TabBar`, существующие маршруты |
| Телевизор и его состояние | `TvScreen` |
| Постер и карточки контента | `Poster`, существующие `.tile`, `.card` |
| Текущее воспроизведение | `NowBar`, общий контекст воспроизведения |
| Шкала перемотки ТВ | `PlaybackTimeline` на странице ТВ и в пульте. Поддерживает касание и клавиатуру |
| Добавление видео | `AddField`, `Library` |
| Выбор устройства / озвучки | `PickDialog`, `VoiceDialog` |
| Сообщения и темы | `Notice`, `ThemeSwitch` |
| Иконки | `Icons.tsx`; не добавлять библиотеку без согласования |
| Демонстрационные разделы | `DemoNote`; демонстрация не должна выглядеть как готовая функция |

Для действий предусматривать обычное, активное, disabled, загрузочное и ошибочное состояния. Для списков — загрузку, пустой результат и ошибку. Статус подключения и воспроизведения должен быть понятен не только по цвету. Сохранять введённые данные при исправимых ошибках.

## Адаптивность и доступность

Сначала проектировать для телефона. Основные действия должны быть доступны касанием, без hover; для новых основных кнопок ориентироваться на область касания не менее 44×44 px. Это правило новых изменений, а не утверждение, что все старые элементы уже соответствуют ему.

Использовать существующие адаптивные правила CSS: в файле есть несколько порогов и поздние переопределения, поэтому перед изменением проверять весь каскад. Сохранять нижнюю навигацию и доступность текущего воспроизведения, не перекрывать ими содержимое. Диалоги должны помещаться на узком экране.

Использовать семантические кнопки, подписи для полей и доступные имена иконок. Сохранять видимый `:focus-visible` и поддержку `prefers-reduced-motion`. Новые изменения должны учитывать обе темы, длинные названия, отсутствующий постер и недоступный телевизор.

## Изменения системы

Сначала искать существующий токен или компонент. Новую общую сущность оформлять переиспользуемо и описывать здесь. Не создавать отдельные палитры и стили для каждого источника контента. Большую смену визуального направления согласовывать; текущий стиль принят пользователем за основу.
