# EasyTv

Локальный сайт, который находит телевизоры в домашней сети и запускает на них видео: файлы с компьютера и по прямым ссылкам, ролики с YouTube и аниме с animego. Для воспроизведения нужен телевизор с совместимым DLNA/AVTransport.

## Запуск

Нужны Docker Desktop и Git for Windows. В cmd из папки проекта:

```cmd
run.cmd
```

В PowerShell: `./run.cmd` (либо `./run.ps1`, если разрешён запуск скриптов).
Обёртки используют Git Bash и существующий `run.sh`, поэтому команды одинаковы:
`run.cmd down`, `run.cmd logs`, `run.cmd discover`, `run.cmd rebuild`, `run.cmd test`, `run.cmd native`.
ExecutionPolicy для запуска обёртки задаётся только дочернему процессу, системная настройка не меняется.

В Git Bash, а также на Linux/macOS с установленным Docker:

```bash
./run.sh
```

Скрипт сам определит IP компьютера в сети, соберёт образ, поднимет контейнер и откроет http://localhost:8080. С телефона сайт открывается по адресу, который скрипт напечатает в конце.

| Команда | Что делает |
|---|---|
| `./run.sh` | собрать и запустить |
| `./run.sh down` | остановить |
| `./run.sh logs` | логи сервера |
| `./run.sh discover` | показать телевизоры, которые видно с этого компьютера, и их адреса |
| `./run.sh rebuild` | пересобрать без кэша, в том числе обновить yt-dlp (если YouTube перестал скачиваться) |
| `./run.sh test` | прогнать тесты |
| `./run.sh native` | запустить без Docker (Python 3.11+, Node.js, желательно ffmpeg) |

Настройки лежат в `.env`, он создаётся из `.env.example` при первом запуске.

## Как пользоваться

1. На главной видны найденные телевизоры. Экран светится, если телевизор в сети. Поиск идёт каждые 15 секунд, кнопка «Искать сейчас» запускает его сразу. Если телевизор не нашёлся сам, впишите его IP в поле «Добавить по адресу».
2. Откройте телевизор. Выберите файл на компьютере, перетащите его или вставьте прямую ссылку на видеофайл либо ссылку на YouTube в поле «Добавить». Скачанное видео появится в библиотеке.
3. Когда видео готово, нажмите «Показать». На экране телевизора на странице видно, что играет, сколько прошло, есть пауза и стоп.

4. **Каталоги** — поиск по animego. На странице тайтла выберите серию и озвучку, нажмите «Смотреть» и решите, где показать: в этом браузере или на телевизоре. Видео идёт через сервер без скачивания; стрелка рядом с серией скачивает её в библиотеку. «Сохранить в кинотеатр» кладёт тайтл в раздел **Кинотеатр**, там же видно, на какой серии вы остановились.

Библиотека видео общая для всех телевизоров. Она и список найденных телевизоров хранятся в `data/` и переживают перезапуск. Тема (светлая, тёмная или как в системе) переключается в правом верхнем углу и запоминается в браузере.

На странице телевизора и в пульте для телефона кнопки ±10 секунд перематывают видео. Если ТВ сообщает длительность, можно выбрать момент на шкале. Перемотка во время воспроизведения и на паузе зависит от поддержки команды `Seek` телевизором и формата видео.

В разделе «Дальше» у каждого телевизора своя очередь. Готовое видео из библиотеки можно поставить в неё кнопкой «В очередь». Для серии из каталога нажмите «Смотреть», выберите телевизор и нажмите «В очередь». Чтобы начать или перейти дальше вручную, нажмите «Следующее видео» на странице ТВ или в пульте. Пункты можно удалить из списка. Очередь сохраняется при перезапуске сервера.

Когда EasyTv видит, что телевизор дошёл до конца текущего видео, он запускает следующее, даже если страница закрыта. Для автоперехода телевизор должен сообщать адрес, длительность и позицию текущего видео через AVTransport. Ручной запуск следующего пункта доступен и без этих данных.

## Как это устроено

### ИИ улучшение через RelayVSR

Нужны NVIDIA GPU, Docker с поддержкой CUDA и около 10,2 ГБ для весов. На Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/download-relayvsr.ps1
./run.cmd ai
```

Команда `ai` собирает и запускает оба сервиса: EasyTv и RelayVSR. В Windows она проходит через
`run.cmd` → `run.ps1` → `run.sh`; также можно вызвать `./run.ps1 ai` или `./run.sh ai` напрямую.

Веса находятся в `D:\RelayVsrModel`, подключаются только для чтения и не включаются в образ.
Скрипт продолжает прерванное скачивание и проверяет SHA-256. Путь меняется через `RELAYVSR_MODEL_DIR`
в `.env`; для Linux укажите абсолютный путь к каталогу с `wan.safetensors` и `flash.safetensors`
из [официального репозитория весов](https://huggingface.co/kopper/RelayVSR/tree/751954dc8adf34aa1d636a39fc548b9089703c85).
Для постоянного запуска с моделью установите `EASYTV_AI=on` и используйте обычный `run.cmd`.

При первом задании контейнер загружает веса в GPU один раз и оставляет модель в памяти для
следующих роликов. Для каждого ролика создаётся новая история кадров и KV-кэш. При отмене или
смене приоритета обработка прерывается между кадрами, веса остаются загруженными. После падения
процесса или зависшей отмены (90 секунд) процесс заменяется, и следующий запуск снова загрузит веса.
Выключение ИИ в интерфейсе не выгружает модель: для освобождения её видеопамяти остановите контейнер
`relayvsr` в Docker Desktop или весь EasyTv через `run.cmd down`.

В интерфейсе включите **«ИИ улучшение»**. Настройка общая для дома и сохраняется на сервере.
Новый запуск на ТВ или в браузере проходит через RelayVSR; очередь заранее готовит первые два
ожидающих видео каждого ТВ. Фоновая обработка не запускает телевизор. Неподготовленный ролик
получает приоритет над фоновой работой; прерванная фоновая обработка позднее начинается заново.
Для роликов библиотеки загрузка исходника по-прежнему должна завершиться до запуска; потоковый режим
позволяет не ждать готовности улучшенной копии. Серии каталога модель читает непосредственно по свежей ссылке.

- **В потоке — по мере улучшения:** воспроизведение после готовности первого MP4-фрагмента. При скорости
  модели ниже скорости видео будут паузы. Произвольная перемотка недоступна до завершения обработки.
- **Готовый файл — после обработки:** запуск только после готовности всего файла, с HTTP Range.
  Используйте этот режим, если DLNA-плеер не принимает растущий fragmented MP4 без окончательного размера.

RelayVSR увеличивает каждую сторону кадра ровно в 4 раза, без скрытого уменьшения исходника.
Например, 480p превращается в 1920p: это требует больше видеопамяти и поддержки соответствующего
разрешения телевизором. Реальное время не гарантируется. При нехватке памяти показывается ошибка;
система не подменяет ИИ обычным масштабированием. Видео перекодируется в H.264, первая звуковая
дорожка — в AAC. Субтитры и дополнительные звуковые дорожки не переносятся.

Локальная проверка 13.11.2026: RTX 5060 Ti 16 ГБ, Windows/Docker, синтетический ролик
480×270, 24 FPS, 5 секунд → 1920×1080 со звуком. Холодный запуск занял около 101 секунды,
из них 65 секунд — загрузка модели. Повторная обработка в том же процессе заняла 18,5 секунды
(около 0,27× скорости видео), первые байты пришли через 9 секунд, до завершения.
Это разные задания с настоящим инференсом, без переиспользования готового файла; хеши декодированных
видеокадров совпали. Первый прогон дополнительно включает инициализацию вычислительных ядер.
Пик общей занятой видеопамяти с рабочим столом — около 15 ГБ. Это проверка интеграции,
не оценка качества на фильмах и не гарантия скорости/совместимости с ТВ. Для этой конфигурации
предпочтительна предварительная обработка; более высокие разрешения могут не поместиться в память.

Оригиналы остаются в библиотеке. Улучшенные копии находятся в `data/enhanced`; лимит кэша задаёт
`RELAYVSR_CACHE_GB` (30 ГБ по умолчанию). Старые готовые копии удаляются по мере заполнения, кроме
читаемых сейчас; активное чтение может временно удерживать объём выше лимита. Незавершённые копии
после перезапуска удаляются, очередь отправляет задания повторно. Временные ссылки CDN хранятся
только в памяти процесса. Отключение тумблера прекращает подготовку очереди; начатое воспроизведение
на ТВ и обработка запрошенного ролика не обрываются. В браузере смена режима переоткрывает видео.

Сервис модели доступен внутри Docker как `http://relayvsr:8090`, на компьютере — только через
`http://127.0.0.1:8090`. Для native-сервера задайте `EASYTV_RELAYVSR_URL=http://127.0.0.1:8090`
и подключите в контейнер модели тот же каталог `data/videos`. Логи: `run.cmd logs`.
Исходники модели закреплены на `e856773350f53036d825404c9ea9228e6dffadca` (Apache-2.0), зависимости
инференса устанавливаются по upstream `uv.lock`; в основной сервер PyTorch не добавляется.

### Источники и воспроизведение

- **Поиск.** Обычный способ — SSDP (multicast), но из Docker он в домашнюю сеть не выходит. Поэтому телевизоры находятся тремя путями:
  1. `run.sh` перед запуском ищет телевизоры с самого компьютера (там multicast работает) и передаёт в контейнер адреса их описаний (`EASYTV_TV_LOCATIONS`);
  2. сервер сам проверяет адреса из `EASYTV_TV_HOSTS` и из поля «Добавить по адресу»: по IP он перебирает типичные адреса описания DLNA (у Samsung это порты 7676, 9197, 52235);
  3. каждый найденный телевизор запоминается, и дальше сервер просто читает его описание по HTTP, чтобы понять, в сети ли он. HTTP через Docker проходит без проблем.
- **Воспроизведение** — UPnP AVTransport: телевизору отправляется ссылка на видео (`SetAVTransportURI` + `Play`), и он сам скачивает его с сервера по HTTP с поддержкой HTTP Range.
- **animego** — адаптер `infrastructure/animego/` за портом `CatalogSource`: поиск, карточка (JSON-LD), серии и озвучки из AJAX-эндпоинтов сайта, прямые MP4 из плееров CVH (до 1080p) и Kodik (720p). Aniboom отдаёт только HLS, его без ffmpeg пока не показать. Ссылки временные и привязаны к IP, поэтому сервер получает свежую прямо перед просмотром и сам проксирует видео через `/stream/...` с Range и DLNA-заголовками. Если сайт поменяет вёрстку, на экране будет понятная ошибка, а тесты на сохранённых страницах (`backend/tests/fixtures/animego/`) покажут, что именно сломалось.
- **YouTube** — ролик скачивается через [yt-dlp](https://github.com/yt-dlp/yt-dlp) (поддерживаемый форк youtube-dl с тем же API; оригинальный youtube-dl с YouTube сейчас почти не работает) в H.264 + AAC до 1080p, затем показывается как обычный файл.
- **Прямая ссылка** — сервер скачивает видеофайл по HTTP(S) с учётом редиректов. Если в адресе нет расширения, формат определяется по типу ответа или имени файла в заголовке. Файл сохраняется как есть, поэтому воспроизведение зависит от формата и кодеков, которые поддерживает телевизор или браузер.

```
backend/easytv/
  core/            предметная область: модели, порты (интерфейсы), сценарии
    models.py        Tv, Video, PlaybackStatus…
    ports.py         TvDiscovery, TvController, VideoDownloader, VideoStorage, репозитории
    services.py      TvService, VideoLibrary, PlaybackService
    catalog.py       CatalogService (сайты), CinemaService (сохранённые тайтлы)
  infrastructure/  реализации портов
    ssdp.py          SSDP-поиск (multicast + unicast)
    upnp.py          описание устройства и управление через AVTransport (SOAP)
    ytdlp.py         загрузка с YouTube
    animego/         каталог animego: парсеры страниц и плееров CVH, Kodik, Aniboom
    fetch.py         скачивание видеофайлов по прямым ссылкам и серий из каталога
    storage.py, repositories.py, system.py
  api/             HTTP: FastAPI-роуты, DTO, раздача видео телевизорам, хостинг SPA
  container.py     сборка зависимостей (composition root)
  config.py        настройки из переменных окружения
backend/tests/     сценарные тесты через HTTP API с подменёнными сетевыми портами
frontend/          SPA на React + TypeScript (Vite)
scripts/           поиск телевизоров с компьютера для run.sh (PowerShell и Python)
```

Ядро не знает ни про FastAPI, ни про сокеты: сценарии работают только с портами, а `container.py` подставляет реальные адаптеры. Тесты подставляют фейковые телевизор и загрузчик и проверяют сценарии целиком.

## Если что-то не работает

- **Телевизоров не видно.** Запустите `./run.sh discover`: он покажет адреса описаний телевизоров, которые видно с компьютера. Любой из них можно вставить в поле «Добавить по адресу» на сайте или в `EASYTV_TV_HOSTS`. Если с компьютера телевизоров не видно, проверьте, что они включены, а сеть в Windows «Частная».
- **Хочется, чтобы поиск работал прямо из контейнера.** Поставьте `EASYTV_NETWORK=host` в `.env`: контейнер будет в сети компьютера. На Linux это работает сразу; в Docker Desktop сначала включите Settings → Resources → Network → Enable host networking (версия 4.34+; работает ли там multicast, зависит от версии Docker Desktop). Самый надёжный вариант без Docker — `./run.sh native`.
- **Телевизор не может воспроизвести видео** (ошибка или чёрный экран). Брандмауэр Windows должен пускать входящие подключения на порт 8080 (при первом запуске Windows может спросить, разрешить ли доступ). Сеть в Windows должна быть «Частной».
- **Телевизор спрашивает разрешение на подключение.** Подтвердите один раз пультом. Чтобы не спрашивал совсем, на Samsung: Настройки → Общие → Диспетчер внешних устройств → Диспетчер подключения устройств → Уведомление о доступе.
- **Не скачивается с YouTube.** Обновите yt-dlp: `./run.sh rebuild`.

Регрессионные проверки Windows-обёрток: из корня репозитория выполните
`python -m pytest scripts/tests`. Они запускают настоящую цепочку cmd → PowerShell → Git Bash
в отдельном временном каталоге, подменяя Docker и открытие браузера.

```bash
cd backend && python -m venv .venv && . .venv/bin/activate && pip install -e '.[test]'
EASYTV_DATA_DIR=../data python -m easytv      # API на :8080
python -m pytest                               # тесты
# Из корня репозитория с backend в PYTHONPATH:
python -m pytest backend/tests relayvsr/tests   # также очередь/HTTP сервиса модели, без GPU

cd frontend && npm install && npm run dev      # SPA на :5173, запросы проксируются на :8080

EASYTV_ANIMEGO_URL=https://animego.me          # домен animego, если сайт переедет
```
